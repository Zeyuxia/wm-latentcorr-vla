HF 上传命名与说明指南
生成时间：2026-05-29

为什么需要这个文件
==================
上传 Hugging Face 时，权重文件本身通常只能看到文件名。
如果没有额外说明，后面很容易忘记：
- 这个权重来自哪个实验
- 是主线、消融、诊断，还是负例参考
- 应该用 base / pred / residual / oracle 哪条推理路径
- 是否需要配套 failure table / EVAC / config

所以建议 HF 仓库至少保留两个说明文件：
1. HF_UPLOAD_WEIGHT_MANIFEST_20260529_CN.txt
   详细清单，记录每个权重的来源和作用。
2. HF_UPLOAD_NAMING_GUIDE_20260529_CN.txt
   简短命名指南，方便快速浏览。

HF 仓库推荐目录结构
==================
建议上传后保持如下结构：

smolvla/
  core/
  ablation/
  expanded_mainline/
  expanded_ablation/
  failure_tables/
  eval_summaries/
act/
  core/
  expanded/
  eval_summaries/
pi05/
  expanded/
evac/
metadata/

不要把所有 .pt / .safetensors 平铺在根目录。
平铺会让文件名越来越难读，也很难判断哪些是主线，哪些是消融。

HF commit message 建议
=====================

   add SmolVLA LatentCorr core checkpoints and failure tables

2. 上传 ACT：
   add ACT LatentCorr core and paired-eval artifacts

3. 上传 EVAC / PI05：
   add EVAC and PI05 dependency checkpoints

4. 上传 expanded：
   add expanded checkpoint histories for disaster recovery
